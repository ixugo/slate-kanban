# Slate 桌面端

桌面程序启动内置 Slate 服务，并在 Wails 窗口中打开同一套 React 网页。它和独立服务默认都读取 `~/.slate-kanban/config.toml`，共享 SQLite、附件目录和端口配置。一个配置目录同一时间由一个 Slate 进程使用。切换启动方式前，先退出正在运行的 Slate 应用或独立服务。独立服务仍可用 `-conf` 指定其他配置目录。要同时使用独立的 SQLite 数据库，在自定义配置中填写该数据库的绝对路径。

macOS 关掉窗口后，Slate 仍在状态栏运行。点击状态栏的 Slate 图标可查看最近有活动的卡片，选中一张即可回到窗口并打开卡片详情。要关闭内置服务，请从菜单退出 Slate。网页和原生菜单均可使用简体中文、繁體中文、日文和英文，语言在应用的设置中修改。


## 桌面自动派发

1. 在桌面应用打开「接入 Agent」，选择一张研发模板看板。先在看板设置登记本机 Git 项目根目录。
2. 为要启用的工程师选择本机已安装、可非交互执行的 Claude Code、Codex、Pi 或 Oh My Pi，再点击「启用并保存」。未选宿主的工程师不派发。
3. 在同一页查看执行状态或停用。设置保存在本机配置目录。网页浏览器不提供这组操作。

研发先从「进行中」取任务，再处理「待办」。审查使用测试工程师的独立名额。桌面依据当前看板和服务端租约恢复任务。其他机器可同时用各自身份监听同一看板。桌面端不调用 Python 监听器。

领取任务后先保持租约、检索关联上下文，不立即移入「进行中」。桌面从数据库读取同一看板的任务（包括已完成和归档任务）及评论，让所选宿主只读提取关键词，再结合卡片编号引用、双向依赖、标题、描述、标签和评论召回候选。宿主分批筛选真正相关的历史信息；桌面核对卡片编号、评论编号和原文依据后，将历史上下文与当前任务原文分开交给规划和正式执行（审查同样如此）。历史信息仅供参考，不覆盖当前要求。无相关结果时照常派发；检索失败时留准备失败提示，不提前移列。任务内容变更或租约丢失时废弃旧检索结果。

宿主在任务工作树里改完文件后，如果它的沙箱不允许写 Git 元数据（例如 Codex 的 workspace-write 无法创建 `index.lock`），工作树里剩下的改动由桌面端代为提交，提交说明是「任务编号 标题」。宿主已经自己提交的，桌面端直接使用它的提交。没有任何提交也没有改动，视为未交付。任务本身不需要改仓库时（例如只要求在评论区输出一段内容），宿主回报 `reported`，要发布的内容写进摘要；桌面端确认分支、提交和工作树都没有变化后，把摘要原样发成交接评论并移入「审查」。宿主回报 `reported` 却留下了改动或提交，视为结果不可信，按未确认处理。

如果启动后派发立刻失败，卡片上出现「找不到 Node.js」之类的提示，说明从 Finder 或 Dock 打开的 Slate 只有精简的 PATH。桌面端会自动补上 Homebrew 的 Node 目录；用 nvm、fnm 等安装 Node 时，请改用 Homebrew 安装，或从终端启动 Slate。

遇到已确认的限流或额度错误，工程师显示「不稳定」。立即重试一次后按 5、10、15、30 分钟退避，之后维持 30 分钟。若宿主退出且结果未确认，调度器会在本轮结束或旧租约到期后发出待核对留言。确认旧宿主已停止并检查卡片和专属工作树，再复制该留言中的 `Slate desktop retry: <恢复码>`，作为一条新的人工评论发送。普通评论和旧恢复码不会解除暂停。审查在一份独立的临时检出里进行，宿主可以在其中构建和运行测试（可写运行的 Go 构建缓存放在系统临时目录，运行结束即删）；跑完后桌面端核对检出的提交没变、工作树干净（含未跟踪文件），否则按未确认处理，任务不会移列。审查结论为通过时，桌面端先留下审查证据（评论末尾带 `Slate review: <起点>..<已审提交>` 审批行）。任务有专属分支（`slate/<编号>-xxx`）且领先项目当前分支时，桌面端不再调用模型，直接用内置的 `integrate.py` 在临时工作树里 cherry-pick 已审提交、快进项目当前分支，记下合并提交后把任务移入「完成」，并清理任务工作树和分支。没有提交可合并的任务（例如只在评论区输出内容）直接移入「完成」。主工作区有未提交修改等问题时，现场原样保留，任务停在「审查」，卡片上写明原因；处理好后在卡片下留一条评论，桌面端会直接重试合并，不会重新审查。分支在审批之后又有了新提交时审批作废，重新审查。提交与项目分支有冲突时，桌面端写明冲突并把任务退回「进行中」，研发把分支变基到留言里给出的提交、解决冲突并交接，之后重新审查再合并；结论为待补验（waiting）时留言写明没验证的项，并把任务移进「收件箱」等人处理，人补完把任务放回「审查」，桌面端就会重新审查，不需要再评论；不通过则退回「进行中」。已经在「完成」列、但没有合并记录的存量任务不会被自动退回；人把它们放回「审查」即可走新流程。派发时领取、移列和评论都记在对应工程师名下；同一块看板不要在两台桌面上同时开启派发；同名工程师已持有有效租约的任务，另一台桌面不会再领取或续租。

正式执行的会话以卡片编号和阶段命名。同一台机器上再次使用同一宿主处理该卡片及阶段时，会续接此前的会话。关联检索和拟定方案使用临时对话。

## 构建与安装

- `make desktop/build` 构建本机程序到 `build/desktop/<系统>_<架构>/`。
- `make desktop/asset/linux_arm64 TAG=v1.2.3` 打包单个平台。可将目标替换为 `linux_amd64`、`windows_amd64`、`darwin_amd64` 或 `darwin_arm64`。
- 在 macOS 上运行 `make desktop/assets TAG=v1.2.3`，一次生成五个安装包与 SHA-256 清单，输出到 `dist/desktop/`。打包需要 Go、Node.js 和 Python 3.9+。macOS DMG 使用系统打包工具，Windows 和 Linux 可用 `UPX_BIN=` 跳过 UPX。
- Windows 解压 ZIP 并启动 `slate_desktop.exe`，界面依赖系统 WebView2。Linux 解压 tar.gz 并运行 `./slate_desktop`，界面依赖 GTK4 和 WebKitGTK 6.0。macOS 打开 DMG，将 Slate 拖到「应用程序」。本地构建默认使用临时签名，可设置 `SLATE_DESKTOP_SIGN_IDENTITY` 选用已配置的签名身份。
- 更新入口在「设置 → 关于」。Windows 和 Linux 校验安装包后替换程序并重启。macOS 校验后打开 DMG，退出 Slate 后在 Finder 中安装新版本。应用数据保存在配置目录。
- Windows 图标和清单资源随源码提交。更新网页图标后运行 `go generate -tags slate_desktop,embed_web ./cmd/desktop` 重新生成 Windows 资源。


## 合并后的工作区清理

已合并卡片的详情会列出提交。使用执行合并的本机 Slate 桌面应用打开卡片，可查看清理结果及阻断原因。清洁工作区可重试清理。若有本地文件，可以先查看待移存路径和目标目录，再选择保留现场或确认移存。

移存保留原工作区快照、暂存和未暂存补丁及原索引。目标位于主工作区同级的 `<项目名>-slate-recovery` 目录。操作复用合并回执，需要 Git 与 Python 3.9+。共享看板的网页只显示合并提交。
