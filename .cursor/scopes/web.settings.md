# 看板设置页

## 需求目标

人在网页上管理看板元数据、列与 Trello 式自动化规则，无需登录；变更失败有明确提示，删除类操作需二次确认。

## 页面结构

- 路由 `/b/:boardId/settings`，非法编号或看板不存在时友好说明。
- 页头：看板名、返回看板链接。
- 五个 Tab：常规 / 列 / 工程师 / 自动化 / 导出。

## 自动化（现行）

- **推荐规则**三条（进入起步模板的进行中列记开始、进入完成列记完成、离开完成列清完成），按项目列是否存在显示，已与现有规则等价的隐藏，点「添加」直接 POST（名称为自动句）；**我的规则**列表主行显示名称、开关/编辑/删除，仅当名称不是自动句时再显示摘要行。
- **新建/编辑**：两行句式（当…时 / 就…），动作分组下拉，「再加一个动作」；名称、筛选、时间覆盖模式在默认折叠的「更多选项」（`aria-expanded`）；新规则默认启用，编辑器无启用开关。
- **自动命名**：`buildRuleAutoName` 按触发器、列、动作与五语文案生成一句，超 `RULE_NAME_MAX` 按字符截断加 `…`。
- **推荐等价判定**：触发器、`column_id`、动作序列（含各类型参数，时间 `mode` 默认 `if_empty`）相同且 `condition` 为空，视为已有该推荐。

## 决策

| 项 | 决定 |
|---|---|
| 数据来源 | `useBoardSnapshot`，不连 SSE |
| 缓存 | 成功后 `invalidate` `queryKeys.board(id)`；改名称时同时 `boards` |
| 列排序 | 上/下移按钮 + `reorderColumns`，乐观更新顺序 |
| 删列 | 有卡必须 `move_to` |
| 导出 | 「导出」页签每种格式一行（JSON 完整数据、Markdown 可读文档），用带 `download` 的同源链接下载，不进前端缓存；看板工具栏不再放导出入口 |
| 删项目 | 模态框里输入项目名称才放行（区分大小写，忽略首尾空白，不再用 slug）；弹窗标题是「删除 **项目名** 项目？」，项目名加粗标红且一点就全选，方便复制后粘贴进输入框，下面只有一个输入框；输入框里回车等同点删除 |
| 工程师 | 「工程师」页签（`EngineersSection`）：列表、招募/编辑对话框、解聘确认，保存都走 `PATCH board` 的 `engineers` 整体替换（已有项带 id）；类型有全栈、前端、后端、UI、测试五种（`engineerKinds.ts`，标签同一填充样式、只有颜色不同）；名称必填且不重名、提示词必填、最多 20 位，校验在 `validation.ts` 的 `validateDraft`；每位工程师配随机头像（`EngineerAvatar` 用 `avatar.ts` 的种子特征画 Q 版真人、猫咪两种画风的 SVG，不用图片文件），列表里只展示头像，招募和编辑窗口里头像右下角有小骰子可随机切换（保存时一起提交）；按钮文案是「招募」「解聘」，不叫「创建 agents」 |
| 规则摘要 | 列表副行用 i18n 长摘要；自动名规则不重复展示 |
| 规则校验 | 前端按 `rule.go` 预检，名称可空（保存时自动命名） |

## 验收清单

- [ ] 常规：改名称/说明，slug 只读，删项目要在模态框里输入项目名称，确认后回列表
- [ ] 列：增删改、上下移、agent 指令与 AI/完成列开关
- [ ] 自动化：推荐、列表、简化编辑器、自动命名
- [ ] 导出：JSON 和 Markdown 下载链接指向当前项目，浏览器真的会下载文件
- [ ] 五语言文案完整，`tsc` / `oxlint` / `vitest` 通过
