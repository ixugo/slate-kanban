# v1 范围：免登录、对标 kanzo 的基础能力、能自己管自己

## 需求目标

做出第一个能用起来的版本：一个程序同时提供网页看板和 MCP 服务，不要账号、不要登录。
v1 能用之后，后续的迭代全部记到这个看板上，通过 MCP 建项目、录入任务、移动卡片来管理进度（自举）。

基准是 [kanzo](https://github.com/emanuele-em/kanzo) 的基础能力，在这之上多三样：Trello 式的自动化规则、五种界面语言、
agent 的离线补拉和阻塞等待。

## 决定：不要登录，不要用户系统

| 项 | 以前 | 现在 |
|---|---|---|
| 网页 | 输入管理令牌登录 | 打开就用，没有登录页 |
| REST `/api/v1` | `Authorization: Bearer` | 不认证，所有请求都是"人"（名称固定 `human`） |
| MCP `/mcp` | agent 令牌 / 管理令牌 | 不认证，身份由网址参数自报（见下） |
| 令牌管理 | `/agent-tokens`、令牌表、管理令牌配置 | 全部删除 |
| 安全边界 | 令牌 | 默认只监听 `127.0.0.1`；Host 白名单；跨站写请求拦截（见下） |

### MCP 身份规则

- 网址 `http://127.0.0.1:7070/mcp?name=codex`：`name` 是这个 agent 的名字（小写字母、数字、点、下划线、连字符，首字符是字母或数字，最长 64；不合法返回 400；缺省 `agent`）。
  `human`、`system` 是保留名，不能用。名字决定评论作者、领取者、各自的"读到哪里了"游标，所以每个 agent 要用自己的名字。
- 网址再加 `&role=manager`：管理视图（建看板、改列、改规则、删除、录入任务），操作者类型是"人"，名字缺省 `manager`。
  不加 `role`（或 `role=worker`）：工作视图，操作者类型是 agent，权限和以前的 agent 令牌一样受限（只处理自己领取的卡片）。
- 这不是安全边界，只是让干活的 agent 不会误删东西、上下文里的工具也少一些。真正能碰数据的人，本来就能直接用网页。

### 安全兜底（因为没有了令牌）

1. 默认监听 `127.0.0.1`，README 写明：要给别的机器用，必须放在自己信得过的网络里，或放在带认证的反向代理后面。
2. Host 白名单：请求的 Host 不是 IP 字面量、`localhost`、`*.localhost`，也不在配置 `Server.HTTP.AllowedHosts` 里，就返回 403。防 DNS 重绑定。
3. 跨站写请求拦截：非 GET/HEAD/OPTIONS 的请求带了 `Origin`，且 `Origin` 的主机和请求的 Host 不一致，就返回 403。网页是同源的，MCP 客户端不带 `Origin`，都不受影响。
4. 页面不允许被嵌入别的网站（`X-Frame-Options: DENY`），并带 `X-Content-Type-Options: nosniff`。

## 接口契约（网页和后端对齐）

REST 前缀 `/api/v1`，JSON 字段全是 snake_case，不需要任何认证头。相比以前：

- 删除：`GET /me`、`/agent-tokens` 全部。
- 新增：`GET /boards/:id/activity?before=&limit=`，按时间倒序返回 `{ "items": [事件...], "has_more": bool }`，默认 50 条，最多 200 条；
  `before` 是事件序号，只返回比它小的。事件结构和 `GET /boards/:id/events` 一致。
- 不变：看板、列、卡片、规则、导出、实时流 `GET /boards/:id/stream?after=`（SSE，网页用浏览器自带的 `EventSource`）。
- `GET /connect` 的 JSON：

```json
{
  "base_url": "http://127.0.0.1:7070",
  "install_url": "http://127.0.0.1:7070/install.md",
  "skill_url": "http://127.0.0.1:7070/skills/slate-kanban/SKILL.md",
  "mcp_url": "http://127.0.0.1:7070/mcp",
  "hosts": [
    {
      "id": "claude-code",
      "name": "Claude Code",
      "mcp":   [{ "title": "...", "lang": "sh", "code": "..." }],
      "skill": [{ "title": "...", "lang": "sh", "code": "..." }]
    }
  ]
}
```

  没有 `token_env`。每个 host 的 `mcp` 里依次是：工作视图的命令、管理视图的命令（标题里写明用途）。

## 前端的体积目标

- 首屏只加载看板列表和外框，看板页、设置页、接入页按路由懒加载。
- 不用网页字体，用系统字体栈；Markdown 用自己写的几十行安全渲染器，不引入 react-markdown。
- 服务端对 html、js、css、svg、json 预先 gzip 并缓存，带 `ETag`；`/assets/*` 带一年不变的缓存头。
- 预算：首屏 JS gzip 后不超过 130 kB，整个 `dist` gzip 后不超过 300 kB（构建后用脚本检查）。
