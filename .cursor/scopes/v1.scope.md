# v1 范围：免登录、对标 kanzo 的基础能力、能自己管自己

## 需求目标

做出第一个能用起来的版本：一个程序同时提供网页看板和 MCP 服务，不要账号、不要登录。
v1 能用之后，后续的迭代全部记到这个看板上，通过 MCP 建项目、录入任务、移动卡片来管理进度（自举）。

基准是 [kanzo](https://github.com/emanuele-em/kanzo) 的基础能力，在这之上多三样：Trello 式的自动化规则、五种界面语言、
agent 的离线补拉和阻塞等待。

## 决定：不要登录，不要用户系统

| 项 | 以前 | 现在 |
|---|---|---|
| 网页 | 输入管理令牌登录 | 打开就用，没有登录页 |
| REST `/api/v1` | `Authorization: Bearer` | 不认证，所有请求都是"人"（名称固定 `human`） |
| MCP `/mcp` | agent 令牌 / 管理令牌 | 不认证，身份由网址参数自报（见下） |
| 令牌管理 | `/agent-tokens`、令牌表、管理令牌配置 | 全部删除 |
| 安全边界 | 令牌 | 默认只监听 `127.0.0.1:7070`；Host 白名单；跨站写请求拦截（见 identity.open.go.md） |

### MCP 身份规则

- `http://127.0.0.1:7070/mcp?name=codex`：`name` 是 agent 名字（小写字母、数字、点、下划线、连字符，首字符字母或数字，最长 64；不合法 400；缺省 `agent`）。`human`、`system` 保留。
- `&role=manager`：管理视图（24 个工具），操作者类型 human，名字缺省 `manager`。缺省或 `role=worker`：工作视图（16 个工具），操作者类型 agent。
- 不是安全边界：能访问端口的人可以把 REST 当管理员、用 `role=manager` 获得管理工具。

### 安全兜底

见 `identity.open.go.md`：Host 白名单（含 `/health`）、写请求 Origin 与 Host 一致、`X-Frame-Options: DENY`、`nosniff`。

### 配置

- 默认监听 `127.0.0.1:7070`；改端口、加 `AllowedHosts` 在 `config.toml` 里，**改完要重启进程**（程序只在启动时读一次配置文件，不监听文件变化，也就没有热加载）。
- `JwtSecret` 配置项已删；旧配置文件里多写一行也不影响启动。
- PostgreSQL 只在 DSN 以 `postgres` 开头时启用；看板存储层测试在 SQLite 与 PostgreSQL 上均通过（`make test-postgres`）。

## 接口契约（网页和后端对齐）

REST 前缀 `/api/v1`，JSON 字段 snake_case，不需要认证头。已删除 `GET /me`、`/agent-tokens`。
实时流 `GET /boards/:id/stream`（网页用 `EventSource`）。
`GET /api/v1/connect` 的 JSON 无 `token_env`；各 host 的 `mcp` 步骤含 `kind: worker` 与 `kind: manager`，URL 带 `?name=`。详见 `agent.skill.go.md`。

## 教训：测试辅助文件不要覆盖

`internal/core/kanban` 里有一个**只在测试时编译**的 `export_test.go`，里面是 `PublishForTest`、`RunForTest`、`EmitForTest`、`Unit` 等别名，给 `kanban_test` 包和包内测试用。

曾经新增导出测试时，把同名文件**整份覆盖**成普通测试，上述辅助函数全没了，整个 `internal/core/kanban` 测试包编译失败。

**以后**：新增测试前先看目录里是否已有同名 `*_test.go`；带 `ForTest` 的辅助文件只**追加**函数，业务测试放到别的文件（例如 `board_export_test.go`、`kanbanapi/board_export_test.go`）。`kanbanapi/export_test.go` 里只剩 `WithStreamTimingForTest`，不要和 Core 的辅助文件搞混。
